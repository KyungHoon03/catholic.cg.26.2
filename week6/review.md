### 1. 실습 1에서 조명과 법선 구별

- [x] normal 강도를 바꾸니 명암은 변하지만 외곽선은 유지되는 것 같았다.
- [x] 환경 반사는 처음에 구별하기 어려웠지만, 조명 조건을 분리하고 roughness를 낮추니 대비가 좀 커져 보였다.
- [ ] 조명별 역할과 법선맵의 원리를 코드에서 독립적으로 설명한다. 실제 최종 슬라이더 값은 별도 기록하지 않았다.
- [ ] 나무·돌의 metallic 맵은 0이라는 점과 녹은 유전체라는 점을 코드·맵에서 확인했다.

답의 핵심: normal map은 조명에 쓸 방향을 바꾸며 정점을 추가하지 않는다. ambient와 환경 이미지 반사는 별개의 간접광 근사다. metallic은 반짝임 세기 버튼이 아니라 반사 방식의 구분이다.

### 2. 필터링을 같은 시점에서 비교

- [x] LINEAR와 밉맵 필터, NEAREST와 밉맵 필터를 비교했지만 눈으로 뚜렷한 차이를 구별하지 못했다.
- [ ] 카메라 이동을 켜서 무늬가 시간에 따라 어떻게 달라 보이는지 직접 관찰했다.
- [ ] MIN=LINEAR_MIPMAP_LINEAR, 높이 0.5, 반복 32에서 비등방성 1×·8×를 비교했다. 기기의 확장 상한은 화면 안내를 따랐다.

답의 핵심: LINEAR는 한 레벨의 주변 4텍셀을 섞는다. 밉맵은 축소한 레벨을 사용하고 trilinear는 두 레벨을 혼합한다. 비등방성은 비스듬한 표면의 길쭉한 footprint에 대응한다. 확대 필터는 원본에 없던 세부를 만들어 내지 않는다.

### 3. 실습 2에서 두 조건의 독립성 시연

- [x] 태양 접근을 바꾸니 행성 이동과 황토색 띠의 확대가 보였다.
- [x] 태양 접근을 고정하고 화산 퇴적을 바꾸니 검은 흔적이 넓어졌다.
- [ ] 표시 메뉴에서 두 마스크를 각각 흑백으로 보았다. 값 50에서 안쪽이 회색인 이유를 설명한다.
- [x] 기본 표면 비교를 켰다 끄니 위치는 유지되고 표면 변화만 사라졌다 나타났다.
- [ ] 두 마스크의 독립성을 흑백 화면에서 직접 시연하고 겹침 우선순위를 코드로 설명한다. 기본 역할은 대략 이해했지만 전체 설명은 더 연습해야 한다.

코드: [task2.js](task2.js)의 `dryRegion()`, `volcanicRegion()`, `uBaseline`, 네 개의 `mix()`.

답의 핵심: `uHeat`는 적도 띠 경계와 행성 x를 바꾼다. `uDeposit`은 두 고정된 로컬 지점의 반경을 바꾼다. 각 마스크에 조절값을 곱하므로 50일 때 최대 혼합 비율은 0.5다. 무늬는 `vLocal`, 조명은 월드 공간의 `vP`·법선을 사용한다.

### 4. AI 제안에서 직접 확인한 부분과 남은 설명

다음 두 줄의 값과 적용 순서를 살펴보았다. 건조 영역은 거칠게, 화산 흔적은 매끈하게 만들며 두 번째 혼합이 앞의 결과에 적용된다는 기본 역할은 대략 이해했다.

```glsl
rough=mix(rough,0.95,dry);
rough=mix(rough,0.16,volcanic);
```

- [x] 위 두 줄의 역할과 순서를 살펴보고 대략 이해했다.
- [ ] 마스크 중간값·겹침을 스스로 계산하고 함수 전체를 설명한다.
- [ ] 직접 코드 수정·복원 실험을 수행했다. 이 실험은 아직 하지 않았다.

추가로 살펴볼 지점은 [task2.js](task2.js)의 다음 연결이다.

```glsl
vLocal=aPos;
vP=world.xyz;
vN=mat3(transpose(inverse(uModel)))*aNormal;
```

설명할 내용: 자전해도 무늬가 표면에 붙으려면 로컬 좌표를 사용한다. 태양·눈·표면의 조명 계산은 월드 좌표로 맞춘다. 법선은 역전치로 변환한다. 이 세 줄은 AI가 구현한 부분이며 혼자 설명할 수 있도록 더 살펴볼 필요가 있다.

추가 실험으로 `dryRegion()`의 `mix(0.08,0.85,heat)`에서 0.85만 잠시 0.60으로 바꾸고 태양 접근 100의 마스크를 비교한 다음 0.85로 복원할 수 있다. 예상은 건조 띠가 더 좁아진다는 것이다. 아직 하지 않은 실험이므로 실제로 진행한 뒤 아래 기록을 채운다.

## 9-4 대면 질문의 핵심

| 질문 | 답할 핵심·코드 |
| --- | --- |
| 같은 메시인데 재료가 다른 이유 | UV로 읽는 색·ARM·normal과 PBR 값. 삼각형은 동일 |
| roughness와 normal의 차이 | 미세면 방향의 통계적 분포와 위치별 대표 법선. 실루엣은 그대로 |
| 녹과 금속의 metallic | 녹은 유전체, 노출 금속은 금속. ARM의 B |
| D·F·G의 역할 | 방향 분포·반사 비율·미세면 가림. `directPBR()` |
| sRGB를 적용할 맵 | 색·환경 이미지만 선형화. ARM·normal은 수치 데이터. 중복 선형화 금지 |
| 확대·축소·비스듬한 바닥 | 위 필터링 비교. MAG와 MIN 구분 |
| 광원을 꺼도 보이는 이유 | ambient와 환경 반사를 따로 확인 |
| 첫 조건의 장면 연결 | 행성 x=3−2×heat, 태양 거리 감쇠와 건조 띠 |
| 독립적인 둘째 조건 | 첫 값 고정 후 화산 흔적 반경만 변화 |
| 마스크 겹침과 텍스처 교체의 차이 | 위치별 값을 계산해 색·roughness 혼합. 뒤의 화산 mix 우선 |
| AI 코드 검토·수정 한 곳 | 위 직접 확인 기록. 수행한 사실만 답하기 |
| 발광과 Bloom | 태양 표시는 별도 자체발광 분기, 조명은 별도 point 계산. Bloom은 HDR 색 결과에서 밝은 부분을 추출·번짐·합성하는 후속 패스이며 필수 구현 아님 |
